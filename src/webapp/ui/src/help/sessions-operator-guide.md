# Sessions Operator Guide

Sessions are the run-level record of what happened, when it happened, and where to investigate next.

## What this page is for

Use Sessions to move from a vague problem statement to a specific failing run, phase, or event sequence.

## What to do here

1. Filter sessions by status, mode, or recency.
2. Open the relevant session detail view.
3. Read runtime events, artifacts, and state transitions in order.
4. Use linked pages for deeper action such as Pipeline, Agents, or Artifacts.

## Why this matters

Most operational confusion comes from not knowing whether the problem happened once, repeats often, or is still active. Sessions gives you that answer quickly.

## Use the detail view for

- runtime log review
- state transition review
- artifact verification
- handoff and gate context

## Good operator habit

When reporting a problem, refer to a specific session and event path instead of saying the system is broken in general.
