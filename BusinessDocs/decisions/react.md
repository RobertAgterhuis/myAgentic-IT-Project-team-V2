# Decisions: React / UI Framework

> Stack: react | Status: ACTIVE | Applicable: YES
>
> Created 2026-03-16 during reevaluation. The UI (`src/webapp/ui/`) is a React
> 18 SPA using Radix UI, TanStack Query, Zustand, and Tailwind CSS v4.

---

## Decided Items

| ID      | Priority | Scope                            | Decision                                                                                         | Notes                                                                                                                                                                                                                                   | Date       |
| ------- | -------- | -------------------------------- | ------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| DEC-271 | HIGH     | Phase 3 (React Version Baseline) | What React version is the mandatory baseline, and what is the upgrade policy for major releases? | React 18 is the current baseline. Plan React 19 upgrade within 90 days of its stable release. Test against Radix UI, TanStack, and Zustand compatibility before merging.                                                                | 2026-03-16 |
| DEC-272 | HIGH     | Phase 3 (Component Library)      | What component library/design system governs reusable UI components?                             | Use Radix UI primitives as the base component library. Wrap primitives in project-specific components with consistent API. Avoid mixing multiple component libraries (no Material UI + Radix).                                          | 2026-03-16 |
| DEC-273 | HIGH     | Phase 3 (State Management)       | What state management strategy is mandatory for client-side state?                               | Zustand for client-side UI state; TanStack Query for server state (fetch, cache, sync). Do not duplicate server state in Zustand. Local component state (useState/useReducer) for ephemeral UI state.                                   | 2026-03-16 |
| DEC-274 | HIGH     | Phase 3 (Routing)                | What routing solution is required and what conventions apply?                                    | Use react-router-dom v7. Define routes in a central route configuration. Lazy-load route components for code splitting. Protect authenticated routes with route guards.                                                                 | 2026-03-16 |
| DEC-275 | HIGH     | Phase 3 (Data Fetching Pattern)  | What pattern governs API data fetching, caching, and error handling?                             | TanStack Query is the mandatory data-fetching layer. Define query keys in a central registry. Configure stale/cache times per resource type. Handle loading/error states consistently.                                                  | 2026-03-16 |
| DEC-276 | HIGH     | Phase 3 (Accessibility Baseline) | What accessibility standard is mandatory for React components?                                   | WCAG 2.1 AA compliance minimum. Use Radix UI primitives (built accessible by default). Run `@storybook/addon-a11y` checks on all components. Test keyboard navigation and screen reader compatibility for critical flows.               | 2026-03-16 |
| DEC-277 | MEDIUM   | Phase 3 (Component Patterns)     | What React component patterns are required vs prohibited?                                        | Prefer function components with hooks. Class components are prohibited for new code. Use custom hooks for reusable logic. Colocate component, styles, tests, and stories. Avoid prop drilling beyond 2 levels — use context or Zustand. | 2026-03-16 |
| DEC-278 | MEDIUM   | Phase 3 (Testing Strategy)       | What testing strategy is required for React components?                                          | Unit/component tests with Vitest + Testing Library. Test behavior, not implementation. Minimum 80% coverage for UI components. Storybook interaction tests for complex components. E2E via Playwright for critical user journeys.       | 2026-03-16 |
| DEC-279 | MEDIUM   | Phase 3 (Performance Standards)  | What performance budgets apply to the React SPA?                                                 | Initial JS bundle < 200KB gzipped. Route-level code splitting mandatory. Memoize expensive computations (useMemo/useCallback where profiler shows benefit, not by default). Monitor Core Web Vitals in production.                      | 2026-03-16 |
| DEC-280 | MEDIUM   | Phase 3 (Error Boundaries)       | What error boundary strategy is required?                                                        | Implement error boundaries at route level minimum. Provide user-friendly fallback UI. Log errors to telemetry with component stack trace. Critical sections (data tables, forms) get dedicated error boundaries.                        | 2026-03-16 |
| DEC-281 | LOW      | Phase 3 (Theme/Dark Mode)        | What theming strategy is required?                                                               | Use next-themes for dark/light mode support. Design tokens must support both themes. Tailwind CSS dark: variant for all color usage. Persist user preference. Default to system preference.                                             | 2026-03-16 |
| DEC-282 | LOW      | Phase 3 (Dependency Governance)  | What governance applies to React ecosystem dependencies?                                         | Pin major versions of React ecosystem packages (Radix, TanStack, Zustand). Review changelogs before minor upgrades. Major upgrades require compatibility testing and migration plan.                                                    | 2026-03-16 |
