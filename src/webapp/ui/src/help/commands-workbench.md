# Commands Workbench Guide

The Commands page is where you decide what kind of work the platform should do and what context it should carry into execution.

## What this page is for

Use this page to start new work deliberately. A good command and a good brief prevent bad downstream assumptions.

## What to do here

1. Enter a recognizable project or workstream name.
2. Write a brief that explains outcome, scope, constraints, and urgency.
3. Choose the command mode that matches the actual intent.
4. Check queue state before adding more work.

## Why this matters

Poor command selection causes expensive rework. For example, using CREATE when you really need AUDIT can waste time generating artifacts before understanding the current state.

## How to choose quickly

- Use CREATE for new or end-to-end delivery work.
- Use AUDIT when you need analysis before change.
- Use FEATURE for a scoped enhancement on an existing product.
- Use HOTFIX only when restoring service or reducing urgent production risk.

## Before you submit

Make sure the workspace, project, and repository context are correct. The platform can only reason well when the execution boundary is correct.
