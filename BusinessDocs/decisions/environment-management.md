# Decisions: Environment Management

> Stack: environment-management | Status: ACTIVE | Applicable: YES
>
> Created 2026-03-16. Best-practice decisions for environment tiers,
> configuration management, feature flags, secret management, and deployment
> promotion for full-stack applications.

---

## Decided Items

| ID      | Priority | Scope                                   | Decision                                                               | Notes                                                                                                                                                                                                                                                                                                                                                | Date       |
| ------- | -------- | --------------------------------------- | ---------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| DEC-379 | HIGH     | Phase 2 (Environment Tiers)             | What environment tiers are mandatory?                                  | Minimum three tiers: Development (dev), Staging (pre-production), and Production. Add QA or UAT environments based on compliance/team needs. Each environment must be independently deployable and destroyable. Environment parity: staging must mirror production topology and configuration (minus scale).                                         | 2026-03-16 |
| DEC-380 | HIGH     | Phase 2 (Configuration Management)      | How must application configuration be managed across environments?     | Use environment variables for runtime configuration. Never hardcode environment-specific values. Use a hierarchical config system: defaults → environment overrides → secrets. Configuration schema must be validated at application startup. Document all configuration variables with type, default, and description.                              | 2026-03-16 |
| DEC-381 | HIGH     | Phase 2 (Feature Flags)                 | What feature flag governance is mandatory?                             | Use a feature flag system for progressive rollouts and kill switches. Every feature flag must have: an owner, a description, a target removal date, and documented rollback behavior. Evaluate flags on the server side when possible. Clean up shipped flags within 30 days of full rollout. Never nest feature flags.                              | 2026-03-16 |
| DEC-382 | HIGH     | Phase 2 (Secret Management)             | What environment-specific secret management strategy is required?      | Each environment must have its own secret store. Secrets must never be shared between environments. Use managed secret services (Key Vault, Secrets Manager). Secrets must not appear in deployment logs, error messages, or health check output. Rotation must not require application redeployment.                                                | 2026-03-16 |
| DEC-383 | HIGH     | Phase 2 (Deployment Promotion)          | What deployment promotion rules govern environment progression?        | Code progresses linearly: dev → staging → production. No direct deployments to production. Staging must pass the full test suite (unit, integration, E2E, security) before production promotion. Use the same build artifact across all environments — only configuration differs. Promote artifacts, not source code rebuilds.                      | 2026-03-16 |
| DEC-384 | MEDIUM   | Phase 2 (Infrastructure Consistency)    | How must infrastructure consistency be maintained across environments? | Define all infrastructure as code (IaC). Use the same IaC templates for all environments with parameterized differences (scale, SKU, naming). Drift detection must run at least weekly. Infrastructure changes follow the same promotion pipeline as application code.                                                                               | 2026-03-16 |
| DEC-385 | MEDIUM   | Phase 2 (Environment Access Control)    | What access control rules apply to environments?                       | Production access restricted to SRE/operations team and automated pipelines. Developers have full access to dev, read-only to staging, no direct access to production. All production access must be auditable. Use JIT (Just-in-Time) access for break-glass scenarios.                                                                             | 2026-03-16 |
| DEC-386 | MEDIUM   | Phase 2 (Preview Environments)          | When should ephemeral preview environments be created?                 | Create ephemeral preview environments for every PR that includes user-facing changes. Auto-destroy preview environments when the PR is merged or closed. Share preview URLs in PR comments for stakeholder review. Preview environments use synthetic/seed data — never production data.                                                             | 2026-03-16 |
| DEC-387 | LOW      | Phase 2 (Local Development Environment) | What standards apply to the local development environment?             | Provide a single-command local setup (`npm install && npm start` or `docker compose up`). Document all prerequisites in the README. Use `.env.example` files for required environment variables. Local development must not depend on cloud services — provide local stubs/emulators. Containerized dependencies preferred (database, cache, queue). | 2026-03-16 |
| DEC-388 | LOW      | Phase 2 (Environment Documentation)     | What environment documentation is required?                            | Maintain a living document listing: all environments, their URLs, purpose, owner, access procedure, and deployment method. Include architecture diagrams showing environment topology. Update on every infrastructure change.                                                                                                                        | 2026-03-16 |
