# Decisions: Performance

> Stack: performance | Status: ACTIVE | Applicable: YES
>
> Created 2026-03-16. Best-practice decisions for performance budgets, bundle
> optimization, rendering strategy, image/asset optimization, and performance
> monitoring for full-stack applications.

## Decided Items

| ID      | Priority | Scope                                | Decision                                                             | Notes                                                                                                                                                                                                                                                                                                                             | Date       |
| ------- | -------- | ------------------------------------ | -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| DEC-407 | HIGH     | Phase 3 (Performance Budgets)        | What performance budgets are mandatory?                              | Define budgets for: initial JS bundle (< 200KB gzipped), total page weight (< 1MB), Largest Contentful Paint (< 2.5s), Interaction to Next Paint (< 200ms), Cumulative Layout Shift (< 0.1). Budgets are enforced in CI — exceeding a budget fails the build. Budgets are reviewed quarterly and adjusted to industry benchmarks. | 2026-03-16 |
| DEC-408 | HIGH     | Phase 3 (Bundle Analysis)            | What bundle analysis and optimization is mandatory?                  | Run bundle analysis on every production build (webpack-bundle-analyzer, rollup-plugin-visualizer, or source-map-explorer). Detect and eliminate duplicate dependencies. Tree-shaking must be enabled. Dynamically import large dependencies. Set up CI alerts for bundle size regressions exceeding 10%.                          | 2026-03-16 |
| DEC-409 | HIGH     | Phase 3 (Code Splitting)             | What code splitting strategy is required?                            | Route-based code splitting is mandatory — each route loads its own chunk. Component-level splitting for heavy UI components (charts, editors, maps). Shared vendor chunks for common dependencies. Prefetch next-likely routes on user interaction. Target initial load: only code needed for the first render.                   | 2026-03-16 |
| DEC-410 | HIGH     | Phase 2 (Server Response Time)       | What server response time targets are mandatory?                     | API response time targets: p50 < 100ms, p95 < 500ms, p99 < 1s for standard CRUD endpoints. Background processing endpoints may have higher thresholds (documented in API spec). Monitor response times per endpoint. Alert on sustained p95 degradation > 20% from baseline.                                                      | 2026-03-16 |
| DEC-411 | MEDIUM   | Phase 3 (Image Optimization)         | What image optimization standards are mandatory?                     | Use modern image formats (WebP for photos, SVG for icons/illustrations, AVIF where supported). Implement responsive images with `srcset` and `sizes`. Lazy-load below-the-fold images. Set explicit `width` and `height` to prevent layout shifts. Use a CDN with image transformation for on-the-fly resizing.                   | 2026-03-16 |
| DEC-412 | MEDIUM   | Phase 3 (Font Loading)               | What font loading strategy is required?                              | Use `font-display: swap` to prevent invisible text. Preload critical fonts (`<link rel="preload">`). Subset fonts to include only required character sets. Self-host fonts (avoid third-party font CDNs for privacy and performance). Limit to 2 font families, 4 weights maximum.                                                | 2026-03-16 |
| DEC-413 | MEDIUM   | Phase 3 (Rendering Strategy)         | What rendering strategy should be selected for different page types? | Use SSR (Server-Side Rendering) or SSG (Static Site Generation) for SEO-critical and public-facing pages. Use CSR (Client-Side Rendering) for authenticated dashboard/app pages. Use streaming SSR or React Server Components when supported and beneficial. Document rendering strategy choice per route.                        | 2026-03-16 |
| DEC-414 | MEDIUM   | Phase 3 (Prefetching & Preloading)   | What resource prefetching rules apply?                               | Prefetch (`<link rel="prefetch">`) route chunks for likely next navigation. Preload (`<link rel="preload">`) critical resources (fonts, CSS, above-the-fold images). Use `dns-prefetch` for third-party domains. Do not prefetch aggressively — respect user's data saver preference and connection type.                         | 2026-03-16 |
| DEC-415 | MEDIUM   | Phase 2 (Database Query Performance) | What database query performance governance is required?              | Monitor slow queries (threshold: 500ms). All queries serving user-facing endpoints must use EXPLAIN/query plans during development. Paginate all list queries — no unbounded result sets. Use read replicas for heavy read workloads. Cache frequently-read, rarely-changing data. Index all frequently-filtered columns.         | 2026-03-16 |
| DEC-416 | LOW      | Phase 3 (Web Workers)                | When should Web Workers be used for computation?                     | Offload CPU-intensive operations (data transformation, encryption, complex calculations) to Web Workers when they would block the main thread for > 50ms. Use Comlink or similar for ergonomic Worker communication. Workers must not access the DOM. Pool workers for repeated operations.                                       | 2026-03-16 |
