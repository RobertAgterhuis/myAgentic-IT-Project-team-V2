# Decisions: Analytics & Experimentation

> Stack: analytics | Status: ACTIVE | Applicable: YES
>
> Created 2026-03-16. Best-practice decisions for product analytics, event
> tracking, A/B testing, privacy-compliant telemetry, and data-driven decision
> making for full-stack applications.

## Decided Items

| ------- | -------- | ------------------------------------ | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------- |
| DEC-491 | HIGH     | Phase 4 (Analytics Strategy)         | What product analytics strategy is mandatory?              | Implement privacy-first analytics: prefer self-hosted solutions (Matomo, Plausible, PostHog) or privacy-respecting tools over third-party trackers that share data with ad networks. Analytics must respect user consent choices (DEC-482, DEC-486). Distinguish between product analytics (user behavior) and operational monitoring (DEC-349–358) — different tools, different data stores, different retention.        | 2026-03-16 |
| DEC-492 | HIGH     | Phase 4 (Event Tracking)             | What event tracking framework is mandatory?                | Define a structured event taxonomy: `category.action.label` (e.g., `onboarding.step_completed.email_verified`). All events must include: timestamp, anonymized user ID, session ID, page/route, and event-specific properties. Use a single analytics SDK across the application — no fragmented tracking. Document every tracked event in an event dictionary. New events require review before deployment.              | 2026-03-16 |
| DEC-493 | HIGH     | Phase 4 (Privacy-Compliant Tracking) | What privacy rules govern analytics data collection?       | No analytics data collection without user consent (except aggregated, non-personal analytics where legally permitted). Anonymize or pseudonymize all user identifiers in analytics. IP addresses must be anonymized before storage. Do not track across devices/sessions without explicit consent. Honor opt-out signals (consent withdrawal, DNT). Retention: raw analytics max 13 months, aggregated: indefinite.       | 2026-03-16 |
| DEC-494 | MEDIUM   | Phase 4 (A/B Testing)                | What A/B testing / experimentation framework is mandatory? | Use a feature flag system (DEC-381) as the foundation for experiments. Define every experiment with: hypothesis, primary metric, sample size, duration, and success criteria — before launch. Use statistical significance (95% confidence) as the threshold for making decisions. Experiments must have an owner and a maximum duration (default: 4 weeks). Clean up concluded experiments within 2 weeks of decision.   | 2026-03-16 |
| DEC-495 | MEDIUM   | Phase 4 (Conversion Tracking)        | What conversion tracking strategy is required?             | Define key conversion events (sign-up, activation, upgrade, retention milestones). Build conversion funnels and measure drop-off at each step. Attribute conversions to source (UTM parameters, referrer, campaign). Server-side conversion tracking is preferred over client-side for accuracy and ad-blocker resilience. Share conversion data with marketing through defined data contracts — not raw database access. | 2026-03-16 |
| DEC-496 | MEDIUM   | Phase 4 (Product Metrics / KPIs)     | What product metrics must be instrumented?                 | Instrument at minimum: acquisition (new sign-ups/period), activation (completed onboarding), engagement (DAU/WAU/MAU, session duration, key action frequency), retention (cohort-based, D1/D7/D30), and revenue (MRR, ARPU) if applicable. Use the AARRR (Pirate Metrics) or North Star framework. Review product metrics weekly. Dashboard accessible to product and engineering teams.                                  | 2026-03-16 |
| DEC-497 | MEDIUM   | Phase 4 (Session Replay)             | What session replay governance applies?                    | Session replay (FullStory, PostHog, LogRocket) is permitted only with explicit user consent. Mask all sensitive fields (passwords, PII, payment data) in replay recordings. Exclude authenticated-only pages from replay by default — opt in per page. Set replay retention maximum 30 days. Restrict access to session replays to product and UX teams. Disable in regulated industries unless compliance-approved.      | 2026-03-16 |
| DEC-498 | LOW      | Phase 4 (Analytics Data Pipeline)    | What analytics data pipeline architecture is required?     | Separate the analytics data pipeline from the operational database. Use an event-driven pipeline: application → event bus → analytics store. Support batch exports for data warehousing (daily minimum). Provide a self-service analytics query interface for product teams. Schema-on-write for real-time dashboards, schema-on-read for exploratory analysis.                                                           | 2026-03-16 |
