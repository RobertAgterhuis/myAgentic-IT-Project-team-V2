# Dashboard Operations Guide

Use the dashboard first when you need a fast answer to one question: what needs attention right now?

## What this page is for

The dashboard is not a deep-dive workspace. It is the fastest place to see whether the platform is healthy, degraded, blocked, or drifting.

## What to do here

1. Read the status and backlog cards before opening any detailed view.
2. Identify whether the problem is about flow progression, approvals, or telemetry.
3. Open the recommended next page instead of troubleshooting from summary metrics alone.

## Why this matters

Starting on the dashboard prevents two common mistakes: opening the wrong diagnostic page first and reacting to a single signal without enough context.

## When to leave this page

- Open Pipeline when the issue is phase, gate, or readiness related.
- Open Cockpit when the issue is live operational triage.
- Open Observability when you need evidence behind a metric or alert.

## Good operator habit

Use the dashboard for prioritization, not explanation. Summary cards tell you where to look next, not the final answer.
