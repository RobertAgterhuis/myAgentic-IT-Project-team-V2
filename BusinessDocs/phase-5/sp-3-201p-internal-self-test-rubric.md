## Friction Points Identified

### CRITICAL (blocks adoption)

| #    | Friction Point                                   | Evidence                                                                                                                                                               | Impact                                                                                                                                                                                             | Recommendation                                                                                                                                                |
| ---- | ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F-01 | **No "Start Here" guide for pilot participants** | Onboarding output assumes AI agent as consumer, not a human evaluator. No document explains "you are a pilot participant — here is what you review and in what order." | A human pilot participant would not know where to begin or what sequence to follow. The 6-step mini-cycle is defined in the pilot scope document but not in any artifact the participant receives. | Create a `pilot-participant-guide.md` with: (1) what you're evaluating, (2) reading order with file links, (3) rubric template, (4) where to submit feedback. |

### HIGH (significant friction, workaround possible)

| #    | Friction Point                                            | Evidence                                                                                                                                                                                                                                                                                                       | Impact                                                                                                                                       | Recommendation                                                                                                                                                                                    |
| ---- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| F-02 | **Phase output volume is overwhelming**                   | Phase 1 produces 20 files (5 agents × 4 deliverables each). Phase 2 produces 24 files (6 agents × 4). Total: 44+ files for just 2 phases.                                                                                                                                                                      | A TECH evaluator must determine which files are relevant (likely 6-8 of 24 Phase 2 files). No filter exists.                                 | Add a per-phase summary document (1 page) that lists: key decisions, open risks, and recommended reading order for each evaluator role.                                                           |
| F-03 | **Synthesis report becomes stale after sprint execution** | Master report date: 2026-03-10. Sprint 1 completed: March 24. Sprint 2 completed: April 7. Sprint 3 in progress. The blocker matrix still shows 0 RESOLVED items despite BLK-2-501 (TMS) being resolved in Sprint 2.                                                                                           | Evaluators reviewing synthesis report get an outdated picture. Resolved blockers still appear OPEN.                                          | Implement a "Synthesis Delta" mechanism — either update the master report after each sprint with a "Sprint N Updates" section, or produce a `synthesis-status.md` that tracks blocker resolution. |
| F-04 | **Critic validation checks format, not substance**        | Phase 2 critic validates contract compliance, anti-hallucination protocol, completeness — all PASSED. But it does not evaluate whether the Modular Monolith architecture decision (ADR-001) is technically sound, whether the security threat model is realistic, or whether the data architecture will scale. | False confidence: all agents "APPROVED" may signal quality to non-technical stakeholders, but the architectural substance is not challenged. | Add a "Technical Substance Review" step to the Phase 2 critic, or introduce a separate "Architecture Review Board" gate that evaluates decision quality, not just deliverable format.             |

### MEDIUM (noticeable friction, manageable)

| #    | Friction Point                                                                             | Evidence                                                                                                                                                                                                                   | Impact                                                                                                                                                                | Recommendation                                                                                                                                                                                                                       |

No standalone Sprint 3 gate artifact.                                                              | Pattern inconsistency makes it harder to locate gate decisions across sprints. An evaluator reading the Financial Analyst's output for an open-source project gets mostly "N/A" or "INSUFFICIENT_DATA". | Add a "scope gate" at Onboarding: if project is non-commercial, skip or truncate Sales Strategist (03) and Financial Analyst (04) deliverables. self-assessment. The primary adoption blockers are
**navigation/discoverability** (too many files, no role-specific reading paths,
no phase summaries) and **staleness of synthesis** (reports written at Phase
boundary don't reflect sprint execution progress). These are addressable with
targeted documentation improvements — no architectural changes required.
