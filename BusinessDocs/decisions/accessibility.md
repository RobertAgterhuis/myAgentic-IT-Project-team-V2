| DEC-435 | HIGH     | Phase 3 (WCAG Compliance Level)           | What WCAG compliance level is mandatory?                 | WCAG 2.2 Level AA is the minimum compliance target for all user-facing interfaces. Level AAA should be pursued where feasible (especially for color contrast and text sizing). Document exceptions with business justification. Compliance is part of the Definition of Done.                                                                                              | 2026-03-16 |
| DEC-436 | HIGH     | Phase 3 (Semantic HTML)                   | What HTML semantics requirements apply?                  | Use semantic HTML elements (`<nav>`, `<main>`, `<article>`, `<button>`, `<table>`, `<form>`) as the foundation. Never use `<div>` or `<span>` for interactive elements. Headings must follow a logical hierarchy (no skipping levels). Forms must associate `<label>` elements with inputs. Lists must use `<ul>`/`<ol>`/`<dl>`.                                           | 2026-03-16 |
| DEC-437 | HIGH     | Phase 3 (Keyboard Navigation)             | What keyboard navigation requirements are mandatory?     | All interactive elements must be reachable and operable via keyboard. Tab order must follow visual layout (logical, not DOM-order hacks). Focus must be visible at all times (custom focus styles permitted, but must meet 3:1 contrast ratio). No keyboard traps — users can always Tab/Escape out. Skip-to-content link required on all pages.                           | 2026-03-16 |
| DEC-438 | HIGH     | Phase 3 (ARIA Usage)                      | What ARIA usage rules are mandatory?                     | Follow the first rule of ARIA: prefer native HTML semantics over ARIA attributes. Add ARIA attributes only when native semantics are insufficient (e.g., custom widgets, live regions, dynamic content). Every ARIA role must be implemented completely (all required properties, keyboard interactions). Test ARIA with actual screen readers — not just automated tools. | 2026-03-16 |
| DEC-439 | HIGH     | Phase 3 (Color and Contrast)              | What color contrast requirements apply?                  | Normal text: 4.5:1 contrast ratio minimum (AA). Large text (≥18pt or ≥14pt bold): 3:1 minimum. UI components and graphical objects: 3:1 against adjacent colors. Never convey information by color alone — always provide an additional indicator (icon, pattern, text). Test contrast with automated tools and manual review in both light and dark themes.               | 2026-03-16 |
| DEC-440 | MEDIUM   | Phase 3 (Screen Reader Testing)           | What screen reader testing is required?                  | Test critical user flows with at least one screen reader per platform: NVDA or JAWS on Windows, VoiceOver on macOS/iOS, TalkBack on Android. Screen reader testing is mandatory for: navigation, forms, data tables, modals/dialogs, error messages, and dynamic content updates. Include screen reader testing in the QA checklist for every release.                     | 2026-03-16 |
| DEC-441 | MEDIUM   | Phase 3 (Focus Management)                | What focus management rules apply for dynamic UI?        | When content changes dynamically (modals, drawers, inline edits, route changes): move focus to the new content. On modal close: return focus to the triggering element. On form submission errors: move focus to the first error. Use `aria-live` regions for status messages that shouldn't steal focus. Document focus management behavior in component specs.           | 2026-03-16 |
| DEC-442 | MEDIUM   | Phase 3 (Automated Accessibility Testing) | What automated accessibility testing is mandatory in CI? | Run axe-core (or equivalent) on every page/component in CI. Fail the build on new violations at the "critical" and "serious" levels. Use Storybook's a11y addon for component-level checks. Automated tests catch ~30% of WCAG issues — supplement with manual testing for the remainder. Track accessibility violations as bugs with severity classification.             | 2026-03-16 |
| DEC-443 | MEDIUM   | Phase 3 (Responsive & Zoom)               | What responsive and zoom requirements are mandatory?     | Content must be usable at 200% browser zoom without horizontal scrolling (WCAG 1.4.10). Touch targets must be minimum 44x44 CSS pixels (WCAG 2.5.8). Layout must adapt to viewport from 320px to 2560px. Text must be resizable up to 200% without loss of content or functionality. Test with zoomed-in state in E2E tests.                                               | 2026-03-16 |
| DEC-444 | LOW      | Phase 3 (Motion & Animation)              | What animation accessibility requirements apply?         | Respect `prefers-reduced-motion` media query — reduce or remove animations for users who opt out. No auto-playing content that moves for more than 5 seconds without a pause/stop control. Avoid flashing content (no more than 3 flashes per second). Provide motion-free alternatives for content conveyed through animation.                                            | 2026-03-16 |
