# Decisions: File Storage & Uploads

> Stack: file-storage | Status: ACTIVE | Applicable: YES
>
> Created 2026-03-16. Best-practice decisions for file upload handling, blob
> storage, virus scanning, image processing, and file governance for full-stack
> applications.

---

## Decided Items

| ID      | Priority | Scope                                | Decision                                                                                                                                                                                                                                                                                                                                                                                                                                        | Notes | Date       |
| ------- | -------- | ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----- | ---------- |
| DEC-473 | HIGH     | Phase 2 (Storage Strategy)           | Use object/blob storage (Azure Blob Storage, AWS S3, MinIO) for all user-uploaded and application-generated files. Never store files in the application database (except metadata). Never store files on the application server filesystem (not scalable, not persistent). Organize files with a clear path convention: `{tenant}/{entity-type}/{entity-id}/{filename}`.                                                                        |       | 2026-03-16 |
| DEC-474 | HIGH     | Phase 2 (Upload Security)            | Validate file type by content (magic bytes), not just extension — reject mismatched files. Enforce maximum file size (default: 10MB, configurable per endpoint). Allowlist permitted MIME types per upload endpoint. Rename uploaded files (UUID) — never use the original filename for storage. Scan all uploads for malware before making them accessible. Serve user-uploaded files from a separate domain/CDN (not the application domain). |       | 2026-03-16 |
| DEC-475 | HIGH     | Phase 2 (Access Control)             | All stored files are private by default. Use presigned URLs (time-limited, max 1 hour) for secure file access. Never expose internal storage paths or keys to clients. Verify authorization before generating presigned URLs. Public files (marketing assets, documentation) may use public CDN — explicitly tagged as public in metadata.                                                                                                      |       | 2026-03-16 |
| DEC-476 | MEDIUM   | Phase 2 (Upload Flow)                | Use direct-to-storage uploads (presigned upload URLs) for files > 1MB — bypass the application server. Application server handles: authorization, presigned URL generation, and post-upload metadata registration. For small files (< 1MB), multipart upload through the API is acceptable. Support resumable uploads for files > 50MB. Provide upload progress feedback to the client.                                                         |       | 2026-03-16 |
| DEC-477 | MEDIUM   | Phase 2 (Image Processing)           | Generate thumbnails and responsive variants asynchronously after upload (background job). Use a CDN with on-the-fly image transformation where supported. Strip EXIF metadata from uploaded images (privacy: GPS coordinates, device info). Convert to WebP for serving (original preserved for download). Set maximum image dimensions (e.g., 4096x4096) — reject or resize larger images.                                                     |       | 2026-03-16 |
| DEC-478 | MEDIUM   | Phase 2 (Retention & Cleanup)        | Define retention policies per file type: temporary uploads (24 hours), user avatars (until replaced), documents (per compliance requirements). Implement automated cleanup for expired/orphaned files. Soft-delete files with a 30-day recovery window before permanent deletion. Log all file deletions with actor and reason. Track storage usage per tenant with quota limits.                                                               |       | 2026-03-16 |
| DEC-479 | MEDIUM   | Phase 2 (Virus Scanning)             | Scan all user-uploaded files with an antivirus engine (ClamAV, Microsoft Defender, or cloud-native scanning) before making them accessible. Quarantine files that fail scanning. Notify the uploading user of rejected files. Log scan results (clean/infected/error) for audit. Scanning must not block the upload response — scan asynchronously and update file status.                                                                      |       | 2026-03-16 |
| DEC-480 | LOW      | Phase 2 (Backup & Disaster Recovery) | Enable versioning on blob storage for production buckets. Configure cross-region replication for critical file stores. Backup policies must align with database backup policies (DEC-325). Test file restore procedures quarterly alongside database restore tests. Document RPO and RTO specifically for file storage.                                                                                                                         |       | 2026-03-16 |
